## Overview

**Objective**:

In this project, you'll build and test a RESTful API using Express.js. You'll write tests for your API using Jest and Supertest. The application will be modularized with separate routes and controllers for better organization. Testing will be conducted both manually using Postman and programmatically with Jest.

**Scope and Complexity**:

For your project, you will be building and testing an API using **JavaScript**, **Express**, **Jest**, and **Supertest**.

In class, we practiced unit testing JavaScript functions using Jest. Now, it’s your turn to extend that knowledge to test API endpoints.

The project is estimated to take around **10-15 hours** to complete.

**_You will work individually on this project._**

> ❗️ As a reminder, General Assembly has a zero-plagiarism policy. **_Your project's code must be substantially yours._** Do not copy code from similar projects or other sources. However, using code snippets from the internet to accomplish generic tasks (e.g., parsing a date string) is acceptable.

## Technical Requirements

> ✅ More than `two` items marked incomplete in this section will result in the project receiving a failing grade.

Your application must meet the following requirements:

- The project must be committed to a version control system with clear commit messages reflecting progress.
- The project must follow a modular structure with separate folders for routers and controllers.
- The project must include unit tests for all API endpoints using Jest and Supertest.
- Tests should cover common success cases as well as error cases.

The following RESTful API routes must be implemented and functional:

- GET /resources – Retrieve all resources.
- GET /resources/:id – Retrieve an resource by ID.
- POST /resources – Create a new resource.

## Guidance

### Getting started

Here are some quick tips to get your project started:

- Discuss your app idea with an instructor to get feedback before you dive too deep into planning.
- **_Keep it simple._** Minimum Viable Product (MVP) functionality that works well is better than extra functionality added to an app with bugs
- Prioritize and implement functionality step-by-step, one at a time. Develop features in a way that allows you to test as you go - try your best to follow the flow of data through your app.
- Regularly review the project requirements to ensure you're on track to pass the project. A printable version of the project requirements can be found [here](./assets/project-requirements.pdf).
- Add comments to your code where it makes sense to do so. Most code is self-documenting, and you shouldn't add comments explaining the obvious. Ideally, comments should explain the **_why_** of code where it's necessary.
